# PBS-001: Platform Bootstrap Standard

**Status:** Canonical Draft
**Layer:** Platform Kernel
**Purpose:** Define the single initialization contract for the iPhande Frontend Platform.

## 1. The Kernel Doctrine
The frontend application MUST NOT initialize its features or routing until the Platform Kernel is resolved. The kernel is the ultimate source of truth for business logic, identity mapping, feature flags, and permissions.

The initialization sequence consists of 4 distinct architectural layers:

1. **Identity (Supabase)**: Proves *who* the user is via JWT.
2. **Platform Kernel (FastAPI `/bootstrap`)**: Proves *what* the user is allowed to do and provides their initial platform context.
3. **Feature Modules (React Query)**: Caches the kernel response and maps it to domain logic.
4. **Presentation (Zustand + Expo Router)**: Renders the authorized context.

## 2. The Contract
The kernel exposes a single HTTP GET endpoint:
`GET /api/v1/bootstrap`

The response MUST strictly adhere to the following payload structure:

```typescript
interface BootstrapResponse {
    identity: Identity;
    businesses: Business[];
    selectedBusinessId: string | null;
    permissions: Permission[];
    featureFlags: FeatureFlag[];
    navigation: NavigationItem[];
    dashboard: DashboardSnapshot;
    policy: PolicyData;
    system: SystemState;
}
```

### 2.1 Identity vs Business
- **Identity**: Refers to the physical person logging in. It contains only `id`, `email`, `emailVerified`, and `displayName`.
- **Businesses**: Replaces the legacy "Profile". One identity may operate multiple businesses. Each business has its own `trust`, `plan`, `status`, and `permissions`.

### 2.2 Permissions
Permissions MUST NOT be simple strings or enums. They must be structured to allow for wildcards, delegation, and fine-grained access:
```typescript
interface Permission {
    resource: string;
    action: string;
    scope?: string;
}
```

### 2.3 Feature Flags
Feature flags MUST be structured objects to support gradual rollouts, versioning, and configuration:
```typescript
interface FeatureFlag {
    name: string;
    version: string;
    enabled: boolean;
    configuration: Record<string, any>;
}
```

### 2.4 Dashboard Snapshot
To guarantee an instant first-paint, the bootstrap payload MUST include a lightweight snapshot of the dashboard. The dashboard screen renders this snapshot immediately and may optionally refresh via `GET /api/v1/dashboard` in the background.

## 3. Failure Modes
- **401 Unauthorized**: The identity layer (JWT) has expired or is invalid. The kernel terminates and the presentation layer redirects to `/login`.
- **403 Forbidden**: The identity is valid, but the platform rejects the connection (e.g., account suspended).
- **503 Service Unavailable**: The kernel is offline. The presentation layer MUST render a fallback maintenance screen.
- **Graceful Degradation (Phase 2A)**: If `/bootstrap` returns 404, the frontend will automatically construct a simulated platform payload using legacy endpoints to prevent blocking development.
